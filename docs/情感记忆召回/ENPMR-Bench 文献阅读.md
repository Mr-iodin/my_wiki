# ENPMR-Bench 

​      **ENPMR-Bench 的主要贡献是提出并诊断一种新的记忆检索任务，而不是提出一个新的记忆模型。**它问的是：用户没有指明要回忆什么时，Agent能否理解其潜在情感需求，主动选出合适的个人记忆，并用它给出支持性回答。

​      它的关键发现是：现有 Embedding、LLM 等检索方法在选择有情感支持价值的记忆时仍然存在明显不足。

## 一、为什么认为需要这个基准

​        传统长期记忆评测常问：“用户去年做过什么？”“他喜欢哪种食物？”系统只要从历史中找到事实即可。

​        情感支持中的问题更难。假设用户说：“我做了新点心，可同事都不感兴趣，感觉没人能聊。”用户没有要求查询旧事。系统需要判断，他当下可能更需要**被理解和联结**，于是想起曾乐意和他分享点心的朋友；找出一条语义上相近的“点心制作记录”，未必能满足这种需要。

​        作者将这种能力称为 **Emotional Need-aware Proactive Memory Retrieval（ENPMR，情感需求感知的主动记忆召回）**。这里的“主动”是指用户没有直接索要该记忆，模型自行决定召回哪一条；**并不表示模型可以决定完全不召回**——在论文的任务设定中，每轮都被明确要求选记忆。

 

## 二、基准数据是如何构造的

数据构造大致是“**人物 → 人生主题与记忆 → 历史对话 → 当前求助对话**”。下边是ENPMR-Bench 的数据构造流程：

![截屏2026-10-29 12.05.46](https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2012.05.46.png)

* **Profile：先造人物画像。**图中的 Emily 有年龄、职业，以及目标（Goals）、能力（Powers）、高光经历、关系和偏好。这里的 Powers 指个人能力。
* **Detailing：把画像扩展成具体记忆。**例如“邻居 Ethan 很友善”，被写成一条 `Relationship` 类型的记忆，并生成一段 Emily 曾向 AI 谈起 Ethan 的历史对话。
* **Sorting：按日期排列历史对话。**右边的时间线展示 AI 过去与 Emily 谈过不同话题。这样，Ethan 的记忆就成了助手可从“历史”中召回的内容。
* **Sampling：选定本次要召回的目标。**为当前情感支持场景**预先指定一条目标记忆**，再让 GPT-4o 生成一个用户表达困扰、助手适合使用该记忆的短对话。作者还放入两三条同主题、同类别但细节不同的干扰记忆，让目标记忆更有区分度。图中选了 Ethan 这条关系记忆，并指定当前需求是 **Love and Belonging（爱与归属）**。同时加入同主题、但具体事件不同的干扰记忆。
* **Generating：生成当前求助对话。**Emily 说新做的点心没人感兴趣；AI 在回答中主动提起喜欢她点心的 Ethan。生成结果再经过筛选和人工核验。

> ​      这里的 **“Negative Memory Item” 指干扰候选**，不是说它一定是一段痛苦的“负面记忆”。它的作用是让生成的对话更针对目标记忆：如果随便换成同主题的另一条记忆，回答就不应同样贴切。

这张图也解释了基准的一个重要特点：**先确定目标记忆和需求，再围绕它生成当前场景。**

论文统计为 **11,846 条记忆、1,872 条情感支持对话**，后者平均约四轮。四类需求中，自我实现有 **1,099** 条，爱与归属只有 **180** 条，样本明显不均衡。



## 三、任务到底需要模型做什么

​        每个样本提供当前对话历史 \(H\)、静态用户画像 \(P\) 和个人记忆库 \(M\)。模型要选出一条记忆 \(m\)，并生成下一句回答 \(a_{t+1}\)：
$$
(m,a_{t+1})=\operatorname{LLM}(H,P,M)
$$
所以它实际涉及两个连续判断：

1. **检索判断：**用户现在缺少什么？哪条旧事有助于回应？
2. **生成判断：**选中旧事后，怎样自然地说出来，才不会显得生硬或答非所问？

论文分别评测了这两个阶段。强调了：**“找对记忆”与“用好记忆”不是同一个能力**。



## 四、心理学框架如何进入数据与评分

​        作者借用马斯洛需求层次，挑出四类未满足需求，并由专家设计“需求 → 记忆类型”的对应规则：

| 当前潜在需求               | 模型应优先考虑的个人记忆 |
| -------------------------- | ------------------------ |
| 生理需求：疲惫、饥饿等     | 偏好，例如饮食与休息习惯 |
| 爱与归属：孤独、被拒绝等   | 关系，例如曾给予支持的人 |
| 尊重：自我怀疑、在意评价等 | 高光经历、关系           |
| 自我实现：迷茫、失去目标等 | 目标、能力、高光经历     |

​        论文中的 `power` 是**个人能力与长短处**，不是权力。这张表一方面指导生成测试场景，另一方面用于计算 **TMR（Memory Type Match Rate，记忆类型匹配率）**。

​        一个比较重要的层级差异：**TMR 只问选中的记忆“类别”对不对，不问具体选中了哪段经历。**“关系记忆”可能有很多条；选对关系这一类，仍可能想起不合适的人或事件。

下图为**桑基图（Figure 3）**，将图二中的“模型选了哪类记忆”画出来。

![截屏2026-10-29 12.35.00](https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2012.35.00.png)

​	例如，看左侧 **Love and Belonging** 的粉色节点：如果大部分流向右侧 `relationship`，就符合作者的规则；若较多流向 `highlight`，说明模型倾向用“你以前取得过成绩”回应“我现在缺少理解和陪伴”。作者把后者视为一种需求与记忆类型的错配。

​	这张图最直观地显示了两件事：

1. **不同模型有选记忆的偏好。**有的更多流向 `highlight`，有的更多流向 `power`；它们并非总根据当前需求灵活切换。
2. **`preference` 的流量很小。**生理需求本应更多连接偏好记忆，但图中这条正确路径通常很细。

​	不过，**不能仅凭带宽断定某模型“错了多少”**。左侧 `Self-Actualization` 本来就是数据中最多的需求（论文报告 1,099 条，归属需求只有 180 条），所以它的总带宽天然更大；记忆库中各类型数量也不同。图没有标出“某一需求下选各类型的百分比”。要定量比较，应看按需求归一化后的比例及上一张表的 **TMR**。

​	还有一个研究上的重要区别：图中所谓“错配”，是**不符合作者预设的需求—记忆类型规则**；在真实对话中，某条具体的高光经历也可能帮助一个感到孤独的人。因此，这张图有力展示了模型选择模式与**论文规则**的差异，但不能单独证明每次跨类别选择都缺乏情感支持价值。



## 五、各组实验分别证明什么

### 1. Embedding 检索能力：语义相似够不够？

​        作者让 embedding 模型在个人记忆库中为当前对话排序，比较了 Qwen3-Embedding-8B、doubao-embedding 等，用 Recall@k、Precision@k 和 nDCG 计分。

结果是最好的模型 **Top-1 约 9.46%，Recall@10 约 46.42%**。也就是说，语义检索经常不能把预设的支持性记忆排到前面。

但这个数字应读作**命中预设目标记忆的比例**，不能直接读作“约 90% 的回答会伤害用户”。数据中每个场景主要有一条目标记忆；在这一设定下，Precision@k 基本由 Recall@k 和 \(k\) 决定，提供的独立信息有限。nDCG 则额外反映目标排得有多靠前。

![截屏2026-10-29 12.27.07](https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2012.27.07.png)

每个测试场景有一条预设的目标记忆。`@k` 表示查看检索结果的前 \(k\) 条，表中数字是百分比。

以 **Qwen3-Embedding-8B** 为例：

- **Recall@1 = 9.46**：约 100 个场景中，只有 9 个把目标记忆排在第一。
- **Recall@10 = 46.42**：查看前 10 条时，约 46 个场景能找到目标。
- **Precision@10 = 4.64**：平均每 10 条结果中约有 0.464 条目标记忆。由于每个场景主要只有**一条**目标记忆，这里基本就是 `Recall@10 ÷ 10`，不提供多少额外信息。
- **nDCG@10 = 25.44**：不仅看目标是否进入前 10，还奖励排得更靠前。它低于 Recall@10，说明不少命中的目标记忆排位仍较靠后。

**🌟 结论：**Qwen3-Embedding-8B 在这四个模型中总体最好，但即使取前 10 条，仍有超过一半的场景找不到预设目标。作者据此认为，单靠文本语义相似度不够。



### 2. LLM 选记忆：提示它先分析需求有用吗？

![截屏2026-10-29 12.30.12](https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2012.30.12.png)

每个生成模型有三种条件：

- **base**：自己判断需求、选记忆并回答。
- **w/CoT**：先按提示分析需求与记忆类型，再选记忆并回答。
- **w/Golden**：直接给它预设目标记忆，再让它回答；相当于检验“选记忆这一步做对之后”能达到什么水平。

`TMR` 是**记忆类型匹配率**，0.49 就是 49%。它只检查是否选中了符合规则的类别，例如归属需求选“关系类记忆”，**不等于找对了具体那条记忆**。Golden 已由实验者指定记忆，所以该列用“—”。

后面的 `GPT` 与 `Human` 是**评分者**，并非两种模型：GPT-4o 自动评分和人工评分。各列是`流畅度（Flu.）`、`类人自然程度（Hum.）`、`信息性（Info.）`、`共情（Emp.）`及`平均分（Avg.`）；

**实验条件并非完全相同：**这组 LLM 实验使用了与当前话题相同的候选记忆子集；普通 RAG 和记忆系统实验使用完整记忆库。因此不要直接把不同表中的原始数字当成同等难度的排行榜。

**🌟 结论**：**找准支持性记忆很难；找准之后，回答通常更好；但模型仍需学会恰当地使用这条记忆。**表中的共情分是对生成文本的评价，并非真实用户情绪改善的测量。

**🌟 应用实例：**表6给出了三种条件在具体场景中的测试实例，

![截屏2026-10-29 12.41.19](https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2012.41.19.png)

> ​      用户刚在摄影活动中遭到质疑，觉得“没人理解我”。论文把他的核心需求标为**爱与归属感**：他此刻尤其希望有人理解、接纳自己。

| 条件                           | 回复用了什么信息                       | 作者想展示的问题                                             |
| ------------------------------ | -------------------------------------- | ------------------------------------------------------------ |
| **Base**：普通方法             | 强调他能把废料变成作品、有创作能力     | 更像在肯定**能力与成就**，没有具体回应“缺少理解和接纳”的感受 |
| **w/CoT**：加入推理步骤        | 提起曾在展览上欣赏他作品的小女孩       | 召回“有人理解你的表达”的经历，回应归属需求                   |
| **w/Golden**：直接提供标准记忆 | 提起欣赏他理念的张教授，并建议与他交流 | 展示拿到预设目标记忆后，模型可以如何组织回复                 |

​       `w/CoT`与`w/Golden`  **最关键的区别是“夸你有才华”和“提醒你曾被理解”**。两者都可能有安慰作用，但在这个例子里，后者更贴近用户说的孤立感。`w/Golden` 中的 `Golden`指实验预设的目标记忆，不代表这段回复已被证明对真实用户最有效。



### 3. 回答生成：给对记忆是否真的有用？

在这篇论文的 Table 4 里，区别主要是**记忆怎么建立和取出**；两组最终都由 **DeepSeek-V3** 生成回复。

|            | RAG                                                          | Agentic Memory                                               |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 主要做法   | 把当前对话转成检索查询，用 embedding 从已有记忆库中找相似记忆，再交给生成模型 | 先用记忆系统整理、合并或组织历史信息，再由该系统管理和取用记忆 |
| 表中的变量 | 换用四种 embedding 模型                                      | 换用 Mem0、MemOS、Memu 三套记忆系统                          |
| 可以理解为 | “这次对话该从记忆库找出哪条？”                               | “历史该怎样形成、维护和调用为记忆？”                         |

​	例如，用户说“没人理解我的作品”：RAG 可能直接检索出一段关于张教授欣赏其作品的历史对话；Agentic Memory 系统可能先把过往对话整理成“张教授认同用户的创作理念”这样的记忆，再在需要时取用。**这只是帮助理解的示意**，三套系统的具体处理方式并不完全相同。

有两个容易误读的地方：

1. **Agentic Memory 不是“不检索”**。它通常也会检索；“agentic”在这里强调记忆的建立、组织和管理过程更复杂。两类方法没有绝对的技术边界。
2. **Table 4 不能单独证明哪一类方法更优**。它同时换了记忆构建和检索机制。MemOS 的综合分是 4.46，最好的 RAG 是 4.45，差距很小；它说明具体系统在该实验设置下的表现，不能推出“Agentic Memory 普遍优于 RAG”。

​	对你做情绪轨迹召回而言，**RAG 是更清楚的起点**：固定记忆库和生成模型，只改变检索排序，才能看出“加入轨迹信息”本身有没有贡献。之后再接入 MemOS 等系统，检验方法能否用于更复杂的记忆架构。

​	在使用 DeepSeek-V3 生成回答、GPT-4o 评分的实验中，普通检索方案的共情分最高约 **4.38/5**，MemOS 约 **4.48/5**；直接提供目标记忆时为 **4.91/5**。作者据此认为，选错记忆会拖累最终回答；即使记忆系统会整合历史信息，也还有提升空间。

<img src="https://cdn.jsdelivr.net/gh/Mr-iodin/images@main/img/%E6%88%AA%E5%B1%8F2026-10-29%2014.17.11.png" alt="截屏2026-10-29 14.17.11" style="zoom:70%;" />

**🌟 结论主要有三点：**

- **整体评分接近**：MemOS 最高，为 **4.46**；RAG 中 doubao-embedding 为 **4.45**。仅差 0.01，不能据此认定 MemOS 明显更好。
- **不同方法的强项不同**：MemOS 的共情分最高（**4.48**）；doubao-embedding 的信息分在表中最高（**4.03**）。Mem0 综合分较低（**3.93**）。
- **检索命中率不等于回复质量**：上一张检索表中 Qwen3-Embedding-8B 的召回表现最好，但这里它的回复均分（**4.43**）略低于 doubao-embedding（**4.45**）。两张表测的是不同环节，微小差距也不宜过度解释。

​	不过，`Golden` 是**这套合成任务的预设目标条件**，不能等同于现实中经真实用户验证过的“最佳记忆”。论文也发现，即使给了目标记忆，模型仍有可能使用得不够自然或贴切。



##  六、R&Q部分

 作者一共提出 **4 个 RQ**。它们串起来是在问：

```
记忆找得准吗 → 找对记忆对回复有用吗 → 找对后模型会用吗 → 这个基准能否测出这些问题？
```

| RQ      | 研究问题                             | 主要结论                                                     |
| ------- | ------------------------------------ | ------------------------------------------------------------ |
| **RQ1** | 现有系统能否找出适合情感支持的记忆？ | 效果有限。最好的 embedding 模型 Recall@1 仅 **9.46%**、Recall@10 **46.42%**；LLM 即使从同主题候选中选择，也常选错记忆类型。尤其在“爱与归属”需求下，容易选到展示成就的 *highlight*，而非关系类记忆。 |
| **RQ2** | 记忆检索质量会怎样影响回复效果？     | 提供目标记忆（w/Golden）后，回复评分明显提高，说明**记忆是否合适**是重要因素。CoT 能略微改善选择，但提升有限。 |
| **RQ3** | 即使拿到合适记忆，LLM 能否把它用好？ | 仍有不足。w/Golden 的回复也未达到满分，说明问题不止在检索，还包括怎样自然、恰当地把记忆融入支持性回复。 |
| **RQ4** | ENPMR-Bench 是否有评估价值和难度？   | 作者认为有：它能区分不同检索、记忆和生成方法，并暴露“回复流畅但记忆用错”的问题。论文把 **RQ2 和 RQ4 合在第 6.2 节**讨论。 |

​        有一处需要保留判断：`w/Golden` 是论文预设的目标记忆，并不能单凭评分差距严格证明“检索是唯一或主要的因果瓶颈”；基准的数据和需求—记忆类型映射也带有人工设计成分。这正是后续研究可以检验的地方。
